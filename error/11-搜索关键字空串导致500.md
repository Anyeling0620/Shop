# 搜索关键字传空串导致后端 500

## 错误信息

```
POST /search/goods/search/1/3
{"keyword":""}
-->
{"code":500,"msg":"..."}   // 服务端异常
```

## 原因

search-service 用关键字拼 Elasticsearch 查询。关键字为空串时，拼出的查询 DSL 缺少 `multi_match` 的 `query` 值，ES 拒绝该请求，服务端抛异常返回 500。

前端搜索框初始状态、以及从列表页清空关键字再搜索时，会把 `""` 原样传下去，触发这个错误。

## 修复

前端在 `web/src/assets/api.js` 的 `searchGoods` 里把空串规整为 `null`，后端按「无关键字、只按筛选条件查」处理：

```js
function searchGoods(param, page, size) {
  var body = Object.assign({}, param || {});
  if (body.keyword != null && String(body.keyword).trim() === '') {
    body.keyword = null;
  }
  return request('search', '/search/goods/search/' + page + '/' + size, {
    method: 'POST', body: body,
  });
}
```

后端侧更彻底的修法是搜索服务里判空后不拼 `multi_match`，但那属于 search-service 的改动，本次未动。
