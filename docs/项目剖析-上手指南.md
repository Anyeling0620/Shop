# 爪哇商城（zhuawa-shop）项目剖析 · 上手指南

> 面向「懂 Go 后端、不熟 Java / Spring Cloud」的读者。
> 本文只讲这个仓库里真实存在的代码，所有结论都能对应到具体文件。

## 0. 先用 Go 的视角建立直觉

| Spring Cloud 概念 | Go 里的对应物 | 说明 |
|---|---|---|
| Maven 多模块 | Go workspace / monorepo | 一个根 `pom.xml` 管 11 个子模块 |
| `spring-boot-starter-xxx` | `import _ "github.com/xxx/driver"` + 自动 `init()` | 只要依赖进 classpath，功能自动装配 |
| `application.yml` | viper / 环境变量配置 | 分层覆盖，key 有固定命名空间 |
| `@Autowired` / `@Bean` | 手写 wire / 构造函数注入 | 容器负责创建和装配对象 |
| `@RestController` | `http.HandleFunc` | 方法即路由 |
| Eureka | etcd / consul 服务注册 | 服务名 → 实例地址列表 |
| Gateway | nginx / 自研网关 | 统一入口、路由、鉴权、限流 |
| OpenFeign | 自动生成的 gRPC/http client | 写接口 + 注解，框架生成实现 |
| `@Transactional` | `db.Begin()` / `defer rollback` | 声明式事务，靠 AOP 代理 |
| `ThreadLocal` | `context.Context` | 一次请求的上下文传递 |
| RabbitMQ | 一样 | 异步解耦 |
| Canal | 自己监听 binlog | 伪装成 MySQL 从库订阅变更 |

一句话：**这个项目就是 9 个可独立启动的 Go 服务 + 1 个注册中心 + 1 个网关，用 HTTP 互相调用，靠注册中心找地址。**

## 1. 模块地图（先记住这张表）

| 模块 | 端口 | 角色 | 说明 |
|---|---|---|---|
| `eureka-server` | 8761 | 注册中心 | 所有服务向它报到；访问 http://127.0.0.1:8761 看实例列表 |
| `gateway` | 8081 | 网关 | 唯一对外入口：路由 + JWT 鉴权 + Redis 令牌桶限流 + CORS |
| `web-app` | 18004 | 静态前端 | 纯静态页（`resources/static/*.html`），jQuery + Bootstrap，**没有后端逻辑** |
| `goods-service` | 18001 | 商品服务 | 商品/品牌/类目/规格，MySQL `goods` 库 |
| `order-service` | 18002 | 订单服务 | 购物车、下单，MySQL `order` 库 |
| `user-service` | 18006 | 用户服务 | 登录发 JWT、积分，MySQL `user` 库 |
| `seckill-service` | 18007 | **秒杀服务** | 本项目的核心：Redis 预减库存 + RabbitMQ 异步下单，MySQL `seckill` 库 |
| `search-service` | 18003 | 搜索服务 | Elasticsearch 检索，消费 MQ 同步商品 |
| `canal-service` | 18005 | 数据同步 | 监听 MySQL binlog，把商品变更丢进 RabbitMQ |
| `canal-starter` | - | 自研 starter | 把 Canal 客户端封装成注解（`@CanalEventListener`），类似写了个 Go 的库 |
| `common` | - | 公共 jar | `Result`、`CodeMsg`、JWT、鉴权拦截器、全局异常 |
| `*-service-client` | - | **API 契约包** | 只有接口和 POJO，供别的服务 Feign 调用（重点，见 §3.3） |

依赖方向：

```
common  ←── goods-service-client ←── goods-service
   ↑              ↑                  order-service / search-service / seckill-service
   └──────────────┴── 所有服务的公共底座
```

**为什么拆 client 包？** 因为 Feign 需要「接口定义 + 返回类型」在调用方编译期可见。Go 里你会把 proto 生成到共用包，这里是同一件事。

## 2. 配置是怎么实现的（第一问）

Java 的配置有 **三层**，很多人一开始就是在这里绕晕的。

### 2.1 第一层：父 POM —— 管「版本」

`pom.xml`（根）：

```xml
<parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>2.5.4</version>          <!-- Spring Boot 2.5.4 -->
</parent>

<dependencyManagement>
    <dependency>
        <groupId>org.springframework.cloud</groupId>
        <artifactId>spring-cloud-dependencies</artifactId>
        <version>2020.0.3</version>    <!-- Spring Cloud 2020.0.3 -->
        <type>pom</type><scope>import</scope>
    </dependency>
</dependencyManagement>
```

- `spring-boot-starter-parent` 提供 **默认插件配置 + 依赖版本仲裁**。
- `spring-cloud-dependencies` 用 `import` 方式引入 BOM，统一 Spring Cloud 全家桶版本。
- 结果：**子模块写依赖不用写 `<version>`**，版本由这两处决定。

> ⚠️ 版本组合很关键：Spring Boot 2.5.x 必须配 Spring Cloud 2020.0.x。不要随便升其中一个，否则启动就报 `NoSuchMethodError`。
> ⚠️ 2020.0.x 已经**移除 Hystrix 和 Ribbon**，所以 yml 里的 `feign.hystrix.enabled: true` 是**无效配置**（见 §7）。

### 2.2 第二层：模块 POM —— 管「有什么能力」

每个服务的 `pom.xml` 声明自己需要什么 starter，能力就自动装上了：

| 依赖 | 带来什么 |
|---|---|
| `spring-cloud-starter-netflix-eureka-client` | 启动时自动注册到 Eureka + 心跳 + 服务发现 |
| `spring-cloud-starter-openfeign` | `@FeignClient` 接口自动生成 HTTP 客户端 |
| `spring-cloud-starter-gateway` | 网关（WebFlux 响应式栈） |
| `mybatis-spring-boot-starter` + `mysql-connector-java` + `druid` | MyBatis + 连接池 |
| `tk.mybatis:mapper-spring-boot-starter` | 通用 Mapper，省掉基础 CRUD 的 SQL |
| `spring-boot-starter-data-redis` | `StringRedisTemplate` |
| `spring-boot-starter-amqp` | `AmqpTemplate` / `@RabbitListener` |
| `spring-boot-starter-data-elasticsearch` | ES 客户端 |

**关键理解：Spring Boot 的「自动配置」= 条件装配。**
starter jar 里有 `META-INF/spring.factories`，列出自动配置类；这些类带 `@ConditionalOnClass` / `@ConditionalOnMissingBean`，只有 classpath 上出现对应类、且你没自己定义 Bean 时才生效。
所以「加一个依赖 = 多一个能力」，等价于 Go 里的 blank import 触发 `init()` 注册。**这也是为什么依赖不能乱加**——加了 `spring-boot-starter-web`，就会启动 Tomcat，和 Gateway 的 Netty 冲突（所以 gateway 不能依赖 `common`，见 §7）。

### 2.3 第三层：application.yml —— 管「跑起来什么样」

每个服务一份 `src/main/resources/application.yml`。以 `seckill-service` 为例，逐段解释：

```yaml
server:
  port: 18007                    # 服务端口

spring:
  application:
    name: seckill                # ★ 服务名，Feign/lb:// 靠它找服务，必须全局唯一
  datasource:
    driver-class-name: com.mysql.jdbc.Driver
    url: jdbc:mysql://localhost:3306/seckill?...
    username: root               # ★ 注意：这里没有 password！（见 §7 P0）
    type: com.alibaba.druid.pool.DruidDataSource
    maxActive: 1000              # 连接池参数，Druid 专用 key
  redis:
    host: 127.0.0.1
    port: 6379
    password: 12345678
  rabbitmq:
    host: 127.0.0.1
    port: 5672
    username: guest
    password: guest

eureka:
  client:
    service-url:
      defaultZone: http://127.0.0.1:8761/eureka    # ★ 注册中心地址

feign:
  hystrix:
    enabled: true                # 无效配置（Hystrix 已移除）

mybatis:
  configuration:
    map-underscore-to-camel-case: true    # 数据库 stock_seckill → Java stockSeckill
  mapper-locations: classpath:mapper/*Mapper.xml   # 该目录实际不存在（历史残留）
  type-aliases-package: com.zhuawa.shop.seckill.model
```

**配置的规则（必须知道）：**

1. **key 是固定的命名空间**，不是随便写。`spring.datasource.url` 这 4 段由 Spring Boot 约定，写错就是「配置不生效但也不报错」。
2. **所有服务的 `eureka.client.service-url.defaultZone` 必须指向同一个注册中心**，否则服务之间互相看不见。
3. **配置优先级**（高 → 低）：命令行参数 > 环境变量 > `application-{profile}.yml` > `application.yml` > 代码默认值。
4. **怎么在代码里读配置**：
   - 单个值：`@Value("${auth.skip.urls}") private String[] skipAuthUrls;`（见 `gateway/filter/AuthFilter.java`）
   - 一组结构化配置：`@ConfigurationProperties`（见 `canal-starter/config/CanalConfig.java`，把 `canal.client.instances.*` 绑成对象）
5. **`spring.application.name` 是微服务的身份证**：Eureka 注册用它，`lb://seckill` 找它，Feign 的 `@FeignClient("seckill")` 也是它。

### 2.4 常用改配置对照表

| 我想… | 改哪里 |
|---|---|
| 换端口 | 对应服务 `application.yml` 的 `server.port`；同时改 `gateway` 路由里的 `uri` |
| 换数据库地址/密码 | 各服务 `spring.datasource.url/username/password` |
| 换 Redis | `gateway`（限流用）+ `seckill-service` 两处 |
| 加一条网关路由 | `gateway/application.yml` → `spring.cloud.gateway.routes` |
| 放行某个免登录接口 | `gateway/application.yml` → `auth.skip.urls` |
| 加一个 Feign 调用 | 建 `xxx-service-client` 模块 → 写 `@FeignClient` 接口 → 调用方 pom 引入 + 启动类 `@EnableFeignClients(basePackages=...)` |
| 改 JWT 密钥/有效期 | `common/utils/JwtUtil.java`（注意还有两份拷贝，见 §7） |

## 3. Spring Cloud 是怎么搭起来的（第二问）

### 3.1 五个零件

```
                    ┌──────────────────────────────┐
   浏览器 ──────────▶│  Gateway :8081               │
  (页面在 :18004)    │  · 路由 Path=/goods/** …      │
                    │  · AuthFilter 校验 JWT        │
                    │  · Redis 令牌桶限流           │
                    └───────┬──────────────────────┘
                            │ 按服务名转发
        ┌───────────────────┼────────────────────┐
        ▼                   ▼                    ▼
   goods :18001       order :18002          seckill :18007
        │                   │  Feign            │  Feign
        │                   └──────▶ goods ◀────┘
        │                              user
        ▼
   MySQL goods 库
        │ binlog
        ▼
  canal-service :18005 ──MQ──▶ search-service :18003 ──▶ Elasticsearch

         全部服务 ──注册/心跳──▶ Eureka :8761
```

1. **注册中心 Eureka**：`@EnableEurekaServer`，自己注册自己关掉（`register-with-eureka: false`）。它是「服务电话簿」。
2. **网关 Gateway**：`@EnableEurekaClient` + `spring-cloud-starter-gateway`。路由规则全在 yml 里（**声明式，不写代码**）。
3. **声明式调用 Feign**：接口 + 注解 = 客户端。没有手写 HTTP 代码。
4. **客户端负载均衡 LoadBalancer**：`lb://order` 中的 `lb` 就是它，从 Eureka 拿到实例列表后轮询。它随 `spring-cloud-starter-openfeign` / eureka-client 自动进来，不用额外配。
5. **公共底座 common**：`Result`/`CodeMsg`/JWT/拦截器。所有业务服务 `@ComponentScan` 都要**显式加上** `com.zhuawa.shop.common`（原因见下）。

### 3.2 启动类上的注解 = 开关

以 `order-service/src/main/java/com/zhuawa/shop/order/OrderApp.java` 为例：

```java
@SpringBootApplication                                    // ① 自动配置 + 扫描本包
@EnableEurekaClient                                       // ② 注册到 Eureka
@EnableFeignClients(basePackages = {"com.zhuawa.shop.goods.api",
                                    "com.zhuawa.shop.user.api"})  // ③ 生成 Feign 代理
@MapperScan(basePackages = {"com.zhuawa.shop.order.dao"})  // ④ 扫描 MyBatis Mapper 接口
@ComponentScan(basePackages = {"com.zhuawa.shop.common",    // ⑤ 额外扫描 common 包
                               "com.zhuawa.shop.order"})
public class OrderApp { … }
```

**⑤ 为什么必须手写？**
`@SpringBootApplication` 默认只扫描「启动类所在包及其子包」= `com.zhuawa.shop.order`。
而 `common` 里那些 `@Service`（`AccessInterceptor`、`UserArgumentResolver`）在 `com.zhuawa.shop.common`，不在扫描范围内，不加 `@ComponentScan` 就会 **依赖注入失败 → 启动报错**。这是新手最常见的坑之一。

> Go 类比：相当于你把 `common` 里的 `RegisterHandlers()` 忘了在 `main` 里调用。

### 3.3 Feign：一个接口怎么变成 HTTP 调用

`goods-service-client/.../api/GoodsApi.java`：

```java
@FeignClient(value = "goods")      // 服务名，来自 goods-service 的 spring.application.name
@RequestMapping("/goods")
public interface GoodsApi {
    @GetMapping("/get/{id}")
    Result<Goods> get(@PathVariable(name = "id") Long id);
}
```

调用方注入后直接 `goodsApi.get(1L)`，框架会：

1. 用 `goods` 去 Eureka 查实例列表 → 负载均衡选一个 `http://ip:18001`
2. 按注解拼出 `GET /goods/get/1`
3. 发请求，把 JSON 反序列化成 `Result<Goods>`

**三个必须对齐的点**（不齐就是 404 / 反序列化失败）：

- `@FeignClient("goods")` == 提供方 `spring.application.name`
- 接口上的 `@RequestMapping` + 方法 `@GetMapping` == 提供方 Controller 的完整路径
- 返回类型结构一致（`Result<T>`）

> 这就是为什么一定要有 `*-service-client` 包：调用方不能依赖 `goods-service`（那是可执行 jar，会连它的依赖和配置一起拖进来），只能依赖契约包。

### 3.4 一次请求的完整生命周期

以「秒杀」为例，把链路串起来：

```
1. 浏览器（:18004/seckill.html）
   GET http://localhost:8081/seckill/seckill/list
        │
2. Gateway :8081
   · 路由匹配 Path=/seckill/**  →  StripPrefix=1  →  目标 /seckill/list
   · AuthFilter（GlobalFilter）：从 header / cookie / query 取 zhuawa-shop-token
       - 无 token → 403 + Location 跳登录页
       - 有 token → JwtUtil.parseJWT 校验签名与过期
   · uri: lb://seckill → Eureka 查实例 → 转发 http://ip:18007/seckill/list
        │
3. seckill-service :18007
   · AccessInterceptor.preHandle()：
       - 解析 JWT → 组装 LoginUser → 放进 ThreadLocal（UserContext）
       - 读方法上的 @AccessLimit，needLogin=true 且 user==null → 直接返回 500102
   · UserArgumentResolver：把 ThreadLocal 里的 LoginUser 注入到 Controller 参数
   · SeckillController.list() → Service → DAO → MySQL
   · afterCompletion()：UserContext.clear()（防线程池串号）
        │
4. 返回 Result{code,msg,data} → JSON → 浏览器
```

**注意 StripPrefix=1 的语义**：网关吃掉路径的第一段。
前端 `/seckill/seckill/list` → 吃掉第一个 `seckill` → 服务收到 `/seckill/list` → 匹配 `@RequestMapping("/seckill") + @GetMapping("/list")`。
所以前端基址是 `http://localhost:8081/seckill/seckill`（`seckill.html` 第 42-43 行），看着别扭但是对的。

## 4. 秒杀核心链路（业务重点，必读）

文件：`seckill-service/.../controller/SeckillController.java` + `service/SeckillOrderService.java` + `rabbitmq/*`

### 4.1 为什么要这么设计

秒杀的本质矛盾：**瞬时上万 QPS 打进来，但库存只有几十件，数据库根本扛不住写**。
思路是「层层拦截，把绝大多数请求挡在数据库之前」：

```
请求 10000 QPS
   │ ① 网关限流（令牌桶 1/s，容量 5）      → 挡掉大部分
   │ ② 秒杀 path 校验（60s 有效）          → 挡掉直接刷接口的脚本
   │ ③ 内存标记 seckillOverMap             → 已售罄直接返回，不碰 Redis
   │ ④ Redis DECR 预减库存                 → 原子操作，把库存判断从 MySQL 挪到内存
   │ ⑤ Redis SETNX 一人一单               → 防重复下单
   │ ⑥ 发 MQ 立刻返回「排队中」            → 削峰，请求不阻塞
   ▼
只剩 ≈ 库存数量 的消息进入 MQ
   │ ⑦ 消费者串行落库（DB 事务 + where stock>0 兜底）
   ▼
MySQL 真实扣减
```

### 4.2 分步拆解

**① 启动预热**（`@PostConstruct init()`）
应用启动时把 `goods_seckill.stock_seckill` 全部写进 Redis 的 `seckill:stock:{goodsId}`。
> 问题：只在启动跑一次。补货/新增秒杀商品不会自动刷新（见 §7 P2）。

**② 获取动态 path**（`GET /seckill/path/{goodsId}`）
生成 MD5 随机串，存 Redis `seckill:path:{userId}_{goodsId}`，60 秒过期，返回给前端。
作用：接口地址不是固定的，脚本没法提前拼好 URL 批量刷。**这是「接口防刷」而不是「安全」**。

**③ 执行秒杀**（`POST /seckill/{path}/do/{goodsId}`）

```java
// 1. 校验 path（对不对、过期没）
if (!seckillService.checkSeckillPath(user.getId(), goodsId, path)) return 非法请求;

// 2. 内存标记：本地 ConcurrentHashMap，已售罄直接返回，连 Redis 都不访问
if (Boolean.TRUE.equals(seckillOverMap.get(goodsId))) return 秒杀结束;

// 3. Redis 原子预减库存
long stock = redisService.decr("seckill:stock:" + goodsId);
if (stock < 0) {
    seckillOverMap.put(goodsId, true);            // 打标记
    redisService.set("seckill:goodsOver:" + goodsId, "true");
    redisService.incr("seckill:stock:" + goodsId); // 回补到 0，避免多实例重复扣成负数
    return 秒杀结束;
}

// 4. SETNX 一人一单（key 带 3600s TTL）
boolean first = redisService.setIfAbsent("seckill:orderMark:" + userId + ":" + goodsId, "1", 3600);
if (!first) return 不能重复秒杀;

// 5. 发 MQ，立刻返回 0（排队中），不等落库
mqSender.sendSeckillMessage(sm);
return Result.success(0L);
```

**④ 异步落库**（`MQReceiver.receive`，`@RabbitListener` 监听 `seckill.queue`）

```java
goods = getByGoodsId(goodsId);                        // 查不到商品 → 直接 return（ack，不重试）
if (goods.stockSeckill <= 0) { 标记无货; return; }      // DB 已无货 → ack
if (已存在该用户该商品订单) return;                     // 幂等：重复消息直接丢弃
seckillOrderService.createOrder(userId, goods);       // 事务：扣库存 + 插订单 + 插秒杀单
```

`createOrder` 是真正的**防超卖最后一道闸**：

```java
@Transactional
public Order createOrder(long userId, SeckillGoods goods) {
    int updated = seckillGoodsDao.reduceStock(goods.getGoodsId());
    // UPDATE goods_seckill SET stock_seckill = stock_seckill - 1
    // WHERE goods_id = ? AND stock_seckill > 0
    if (updated == 0) throw new GlobalException(SECKILL_OVER);  // 抛异常 → 事务回滚 → 消息重新入队
    orderDao.insertOrder(order);            // 插 order 表
    orderDao.insertOrderSeckill(orderSeckill);  // 插 order_seckill（user_id+goods_id 唯一索引兜底）
    redisService.set("seckill:orderId:" + userId + ":" + goodsId, orderId); // 写结果缓存
}
```

**⑤ 前端轮询结果**（`GET /seckill/result/{goodsId}`）
返回约定：`orderId > 0` 成功；`-1` 失败（无货）；`0` 排队中。
查询顺序：Redis 结果缓存 → MySQL 兜底 → 看无货标记。

### 4.3 防超卖的三重保障

| 层 | 手段 | 作用 |
|---|---|---|
| Redis | `DECR` 原子预减 | 把 99% 的并发挡在 MQ 之前，不打 DB |
| MQ | 单队列串行消费 | 把并发写变成串行写，DB 压力可控 |
| MySQL | `WHERE stock_seckill > 0` + 事务 | 绝对兜底，即使前面都失效也不会扣成负数 |

**这就是秒杀系统的标准答案**，Go 里你会用 `redis.Decr` + `chan`/kafka + `UPDATE ... WHERE stock > 0`，一模一样。

## 5. 数据同步链路：MySQL → ES

搜索如果直接查 MySQL，商品多了就慢。所以：

```
goods 表发生 INSERT/UPDATE/DELETE
        │
        ▼  （Canal 伪装成 MySQL slave 读 binlog）
canal-service :18005
   MysqlListener（用 canal-starter 的 @CanalEventListener + @ListenPoint 注解声明监听哪张表）
        │  只取出 id 和事件类型，封装 CanalMessage{schema, table, primaryKey, operationType}
        ▼
RabbitMQ 队列 canal.queue
        │
        ▼
search-service :18003
   MQReceiver（@RabbitListener）
        │  DELETE → es.deleteById
        │  其他   → 调 goodsApi.get(id) 拿最新商品 → es.save
        ▼
Elasticsearch 索引
```

**设计要点**：Canal 只负责「通知哪条数据变了」，真正的数据由 search-service 反查 goods-service 拿**最新完整数据**。这样避免 binlog 解析字段的复杂度，也避免「消费到旧消息」。

`canal-starter` 是个自研 starter：用 `@EnableCanalClient` + `@CanalEventListener` + `@ListenPoint` 把 Canal 客户端跑起来。想学「怎么写自己的 starter」，看这个模块最合适——它就是一个标准的 `spring.factories` + `@ConditionalOnProperty` 套路。

## 7. 现有问题清单（按严重程度，建议优先修）

### P0 · 跑不起来 / 一定踩

**1) 秒杀库的建表 SQL 完全缺失**
`sql/` 目录只有 `brand/category/specs/param/template`、`order.*`、`user.user`，**没有** `goods_seckill`、`order_seckill`、`seckill.order`。
代码里 `SeckillGoodsDao` / `OrderDao` 强依赖这三张表，`@PostConstruct` 预热时就会抛异常导致**服务启动失败**。

参考 DDL（按实体字段反推，请按需核对）：

```sql
CREATE DATABASE IF NOT EXISTS `seckill` DEFAULT CHARSET utf8mb4;

CREATE TABLE `seckill`.`goods_seckill` (
  `id` bigint NOT NULL AUTO_INCREMENT,
  `goods_id` bigint NOT NULL,
  `price_seckill` decimal(10,2) NOT NULL,
  `stock_seckill` int NOT NULL DEFAULT 0,
  `start_time` datetime DEFAULT NULL,
  `end_time` datetime DEFAULT NULL,
  `create_time` datetime DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_goods` (`goods_id`)
) ENGINE=InnoDB;

CREATE TABLE `seckill`.`order` (
  `id` bigint NOT NULL,
  `user_id` bigint NOT NULL,
  `goods_id` bigint NOT NULL,
  `goods_name` varchar(255) DEFAULT NULL,
  `goods_count` int DEFAULT 1,
  `goods_price` decimal(10,2) DEFAULT NULL,
  `create_from` int DEFAULT 0,
  `status` int DEFAULT 0,
  `create_time` datetime DEFAULT NULL,
  `delivery_address` varchar(512) DEFAULT NULL,
  `pay_time` datetime DEFAULT NULL,
  `update_time` datetime DEFAULT NULL,
  PRIMARY KEY (`id`)
) ENGINE=InnoDB;

CREATE TABLE `seckill`.`order_seckill` (
  `id` bigint NOT NULL AUTO_INCREMENT,
  `order_id` bigint NOT NULL,
  `user_id` bigint NOT NULL,
  `goods_id` bigint NOT NULL,
  `create_time` datetime DEFAULT NULL,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_user_goods` (`user_id`,`goods_id`)   -- ★ 一人一单的数据库兜底
) ENGINE=InnoDB;
```

**2) `SeckillGoodsDao` 的跨库 JOIN 会失败**
SQL 是 `from goods_seckill gs left join goods g ...`，**没有库名前缀**。MyBatis 在当前连接（`seckill` 库）里解析，所以要求 `seckill` 库里**也存在 `goods` 表**。
两种改法：
- 改 SQL 加库名：`from goods_seckill gs left join goods.goods g on gs.goods_id = g.id`
- 或者干脆不 JOIN：只查 `goods_seckill`，商品信息走 Feign `goodsApi.get()`（更符合微服务边界，但多一次 RPC）

**3) `seckill-service` 的 datasource 没有 password**
`application.yml` 里 `username: root` 但**没有 `password` 行**，会用空密码连接，多半连不上。

### P1 · 能跑但设计不对

**4) 网关路由不统一：一半 `lb://`，一半写死 IP**

```yaml
- id: zhuawa_shop_goods_route
  uri: http://localhost:18001     # ← 写死，绕过 Eureka，goods 无法多实例负载均衡
- id: zhuawa_shop_user_route
  uri: http://localhost:18006     # ← 同样问题
- id: zhuawa_shop_order_route
  uri: lb://order                 # ← 正确写法
```

建议统一成 `lb://goods` / `lb://user`。**这是微服务网关最核心的价值之一**（扩缩容不用改配置）。

**5) `feign.hystrix.enabled: true` 是死配置**
Spring Cloud 2020.0.3 已移除 Netflix Hystrix，这个 key 不会生效，**没有任何降级/熔断能力**。
服务间调用一旦超时，异常会直接冒到用户。正确做法：加 `spring-cloud-starter-circuitbreaker-resilience4j`，或用 Sentinel。

**6) 未登录跳转地址指向网关自身**
```java
private static final String loginURL = "http://localhost:8081/login.html";
```
但 8081 是网关，**不托管静态页**（静态页在 `web-app` 的 18004）。未登录会被 403 跳到一个 404 页面。
应改为 `http://localhost:18004/login.html`。

**7) `AuthFilter` 里 mutate 了 request 但没重建 exchange**
```java
request.mutate().header(COOKIE_NAME_TOKEN, token);   // 结果被丢弃
return chain.filter(exchange);                        // 传的还是原 exchange
```
正确写法：
```java
ServerHttpRequest newReq = request.mutate().header(...).build();
return chain.filter(exchange.mutate().request(newReq).build());
```
目前因为 header 本来就存在，问题没暴露，但下游取不到时会很迷惑。

**8) 登录接口返回的是 UUID，不是 JWT**
`UserService.login()`：
```java
String token = UUIDUtil.uuid();       // ← 生成一个没用上的 UUID
addCookie(response, user);            // cookie 里放的是正确 JWT
return token;                          // 却把 UUID 返回给前端
```
前端如果把 `data` 当 token 存下来用，鉴权必然失败。应返回 cookie 里那个 JWT。

### P2 · 高并发下会出问题

**9) 秒杀失败后 `orderMark` 不清理，用户 1 小时内无法重试**
`setnx` 的 TTL 是 3600s，但「库存不足 / path 非法 / 重复」时都没有 `delete` 这个 key。结果是用户秒杀失败一次，一小时内连正确请求也被判「重复秒杀」。
建议：失败分支里 `redisService.delete(SECKILL_ORDER_MARK + userId + ":" + goodsId)`。

**10) 内存标记 `seckillOverMap` 多实例不一致**
它是 JVM 本地 `ConcurrentHashMap`。多实例部署时，A 实例标记售罄，B 实例不知道，仍会放请求进 Redis。Redis `DECR` 会兜住，所以**不会超卖**，只是没起到「减少 Redis 访问」的作用；补货后也必须重启才能清标记。
更好的做法：直接用 Redis 的 `goodsOver` 标记，或用本地缓存 + Redis pub/sub 广播失效。

**11) 库存预热只在 `@PostConstruct` 跑一次**
服务运行期间新增秒杀商品、补货，Redis 里的库存是旧的。建议加定时任务或管理端接口手动刷新。

**12) Redis 预减成功但 MQ 发送/消费失败 → 少卖**
消息发失败或消费异常，Redis 库存已经 -1，但 DB 没订单。属于**最终一致性问题**，需要补偿：定时对账（Redis 剩余 + DB 已售 = 总量），或失败时回补 Redis。

**13) `order-service.genOrder` 缺分布式事务**
`OrderService.genOrder` 里做了：Feign 扣库存 → 插 order_item → Feign 加积分 → 删购物车 → 插 orders。中间任一步失败，前面的都回不来（代码注释里也写了 `//TODO if distributed transaction necessary?`）。
至少应改成：先本地落单（状态待确认）→ 再扣库存 → 失败则标记取消。或者引入 Seata / 本地消息表 + 补偿。

### P3 · 整洁度 / 隐患

**14) `common` 太重，导致 gateway 无法复用它**
`common/pom.xml` 塞了 `spring-boot-starter-web`（Servlet 栈）+ thymeleaf + knife4j。
Gateway 是 WebFlux（Netty）栈，**不能**引入 web starter（会冲突），所以 `gateway` 里又复制了一份 `JwtUtil`，`user-service` 里还有第三份。
建议拆成 `common-core`（Result/CodeMsg/JwtUtil，零 web 依赖）和 `common-web`（拦截器/参数解析器）。

**15) JWT 密钥硬编码且三处拷贝**
`common`、`gateway`、`user-service` 各有一份 `JwtUtil`，密钥都是 `1a2b3c4d`。改一处漏两处就全乱。应下沉到 `common-core` + 配置化。

**16) `mapper-locations: classpath:mapper/*Mapper.xml` 指向空目录**
全项目没有任何 Mapper XML，DAO 全是注解 / tk.mybatis。这行是历史残留，可以删（不报错，但容易误导后来人）。

**17) `@SpringBootConfiguration` 用在 `WebConfig` 上**
`order-service` / `seckill-service` 的 `WebConfig` 用的是 `@SpringBootConfiguration`，语义上应该用 `@Configuration`。功能上不出错，但属于用错注解。

**18) 秒杀订单与订单服务的 `order` 表不统一**
`seckill.order` 和 `order.orders` 是两套表结构、两套订单模型。真实业务里应该合并到订单服务，秒杀只负责「抢到资格」。目前是教学项目常见简化。

## 9. 学习顺序建议

1. **先读 `common`**（半天）：`Result` / `CodeMsg` / `JwtUtil` / `AccessInterceptor`。这四个文件吃透，鉴权就懂了。
2. **再读 `eureka-server` + `gateway`**（半天）：注解 + yml 就够，代码只有 `AuthFilter` 和 `keyResolver` 两个类。
3. **然后 `goods-service`**（一天）：最标准的三层（Controller/Service/Dao）+ MyBatis + tk.mybatis，是理解 Java 后端的模板。
4. **接着 `order-service`**（半天）：学 Feign 跨服务调用怎么写。
5. **最后 `seckill-service`**（两天）：Redis 预减 + MQ 异步 + 事务防超卖，是面试和实战的核心。
6. `canal-service` + `search-service` 可选，理解「binlog → MQ → ES」这个模式即可。

按这个顺序，一周内能改代码，两周内能重构。
