# 术语手册 · 每个名词是什么、干什么用

> 阅读方式：不用从头背。当成字典，看代码卡住时回来查。
> 每条都按同一结构写：**是什么 → 解决什么问题 → 本项目在哪 → Go 里对应什么**。

---

## 第一部分：按"你会遇到的顺序"讲

### 1. 构建与工程

#### Maven
**是什么**：Java 的构建工具 + 依赖管理器。读 `pom.xml`，去中央仓库下 jar 包，编译、打包、跑测试。
**干什么**：相当于 Go 的 `go mod`（管依赖）+ `go build`（编译）+ `make`（构建脚本）三合一。
**项目里**：根目录 `pom.xml`，每个子目录一个 `pom.xml`。
**Go 对照**：`go.mod` + `go.sum`。

#### POM
**是什么**：Project Object Model，就是 `pom.xml` 这个文件本身。XML 格式，描述"这个项目叫什么、依赖什么、怎么打包"。
**项目里**：`<packaging>pom</packaging>` 的根 POM 表示它只做聚合，不产出代码。

#### 坐标（groupId / artifactId / version）
**是什么**：Maven 里定位一个包的三元组。
```xml
<groupId>com.zhuawa.shop</groupId>   <!-- 组织，类似 Go 的 module path 前缀 -->
<artifactId>seckill-service</artifactId>  <!-- 包名 -->
<version>1.0-SNAPSHOT</version>      <!-- 版本 -->
```
**干什么**：别的模块靠这三个值引用你。项目里 `seckill-service` 就是这么引用 `common` 的。

#### SNAPSHOT
**是什么**：版本号后缀，表示"开发中的快照版"，可以被反复覆盖发布。
**干什么**：正式版（如 `1.0.0`）发过就不能改，SNAPSHOT 可以随时重发。所以改完 `common` 要重新 `install`，否则下游还是旧的。

#### parent POM / 继承
**是什么**：子模块的 `pom.xml` 里写 `<parent>` 指向根 POM，就继承了根的所有配置。
**干什么**：**版本只在一处定义**。项目根 POM 继承 `spring-boot-starter-parent:2.5.4`，所以所有子模块都不用写 Spring 的版本号。

#### dependencyManagement / BOM
**是什么**：只声明"版本清单"，不真正引入依赖。别人 `import` 这个清单后，写依赖时可以省略 `<version>`。
**干什么**：统一版本，避免每个模块各写一个版本导致冲突。
**项目里**：
```xml
<dependencyManagement>
  <dependency>
    <artifactId>spring-cloud-dependencies</artifactId>
    <version>2020.0.3</version>
    <type>pom</type><scope>import</scope>   <!-- import 就是"引入这份清单" -->
  </dependency>
</dependencyManagement>
```

#### module（多模块）
**是什么**：`<modules>` 列出子项目，Maven 按依赖顺序统一构建。
**干什么**：Go 里一个 repo 放多个 package 的 monorepo。

#### classpath
**是什么**：JVM 启动时查找 `.class` 文件和资源文件的路径集合。
**干什么**：`@ConditionalOnClass`、`classpath:mapper/*.xml` 里的 "classpath" 就是它。**依赖只要在 classpath 上，框架就能"看见"它并自动启用功能。**
**Go 对照**：编译时链接进去的包集合。

#### JAR
**是什么**：Java 的打包格式，本质是 zip，里面是编译后的 `.class` 和资源。
**干什么**：`common` 打成 jar 被别人依赖；业务服务打成"可执行 jar"（内含 Tomcat/Netty，`java -jar` 就能跑）。

#### JVM / JDK
**是什么**：JVM 是运行 `.class` 字节码的虚拟机；JDK 是开发工具包（编译器 + 标准库 + JVM）。
**项目里**：`<maven.compiler.source>8</maven.compiler.target>8` → 用 **Java 8** 编译。**别用 Java 17 直接跑**，Spring Boot 2.5 对高版本支持有限。

### 2. Java 语言里必须先懂的三个概念

#### 注解（Annotation）
**是什么**：贴在类、方法、参数上的**元数据标签**，以 `@` 开头。它自己**不执行任何逻辑**，靠框架读取后赋予行为。
```java
@GetMapping("/list")          // 这个标签本身啥也不干
public Result<List<...>> list() { ... }   // 但 Spring 读到它，就把方法和 URL 绑起来
```
**为什么重要**：Spring 全家桶就是"注解驱动"。**看不懂注解 = 看不懂这个项目。**
**Go 对照**：struct tag（`json:"name"`）+ 代码生成。区别是 Java 注解可以在**运行时**通过反射读到并执行逻辑，Go 的 tag 需要自己解析。

#### 反射（Reflection）
**是什么**：程序在运行期检查类结构、读注解、调方法的能力。
**干什么**：框架靠它实现"你写声明，我干活"。比如 Feign 拿到接口上的 `@GetMapping`，在运行时生成实现类。
**代价**：比直接调用慢，启动时开销大。这也是 Spring 应用启动慢的原因之一。

#### 接口（interface）
**是什么**：只定义方法签名，不含实现。
**项目里**：`GoodsApi` 是接口，你从没写过它的实现——**实现是 Feign 在运行时用动态代理生成的**。这就是"声明式调用"的魔法所在。

### 3. Spring 核心：对象是怎么被创建和组装的

#### Bean
**是什么**：由 Spring 容器创建并管理的对象。普通 `new` 出来的对象不叫 Bean。
**干什么**：容器负责创建、注入依赖、调用初始化方法、销毁。
**Go 对照**：你在 `main` 里手工构造好、再传给别人的那个结构体实例。

#### IoC（控制反转）/ DI（依赖注入）
**是什么**：IoC 是思想——对象的创建权从"自己 new"反转给"容器"。DI 是实现手段——容器把依赖塞进对象的字段或构造函数。
```java
@Autowired
GoodsApi goodsApi;   // 你没 new，容器塞给你一个能发 HTTP 的代理对象
```
**为什么用**：解耦 + 可替换（测试时塞 mock）。Go 里你会在 `main` 里手动 wire，或用 `google/wire` 生成。

#### 容器（ApplicationContext）
**是什么**：管理所有 Bean 的注册表 + 生命周期管理器。启动时扫描、实例化、注入、初始化。
**干什么**：`SpringApplication.run()` 干的就是这件事。

#### @Component / @Service / @Repository / @RestController
**是什么**：四个"请把这个类交给容器管理"的标记，语义不同、效果相同。
- `@Component`：通用
- `@Service`：业务层（`SeckillService`）
- `@Repository`：数据层
- `@RestController`：Web 层，且方法返回值直接序列化成 JSON

#### @Configuration + @Bean
**是什么**：`@Configuration` 标记"这是一个配置类"；`@Bean` 标记"这个方法返回的对象请注册成 Bean"。
**干什么**：把**第三方类**（你改不了源码的）注册进容器。
**项目里**：
```java
@Bean public IdWorker idWorker() { return new IdWorker(); }        // GoodsApp
@Bean public Queue seckillQueue() { return new Queue(...); }        // MQConfig
```
**Go 对照**：构造函数 + 手动注册到某个 map 里。

#### @Autowired
**是什么**：告诉容器"这个字段/参数请帮我注入一个 Bean"。
**默认规则**：按类型找，找不到或有多个就报错。

#### @Value
**是什么**：把配置里的单个值注入字段。
```java
@Value("${auth.skip.urls}") private String[] skipAuthUrls;
```
**注意**：key 写错不会报错，只会注入 null——**这是排查配置问题时的头号坑**。

#### @ConfigurationProperties
**是什么**：把一组同前缀的配置绑定成一个对象。
**项目里**：`canal-starter` 的 `CanalConfig` 把 `canal.client.instances.*` 绑成对象树。

#### 自动配置（Auto-configuration）
**是什么**：Spring Boot 的核心机制——根据 classpath 上有什么类，自动帮你创建对应的 Bean。
**怎么实现的**：starter jar 里有 `META-INF/spring.factories`（2.7 后改为 `AutoConfiguration.imports`），列出候选配置类；这些类带条件注解，满足才生效。
**干什么**：你加一个 `spring-boot-starter-data-redis`，就自动有了 `RedisTemplate`，一行代码不用写。
**Go 对照**：blank import 触发 `init()` 注册。区别是 Java 的条件更细（有依赖才装配、你定义了就让我退让）。

#### @ConditionalOnClass / @ConditionalOnMissingBean
**是什么**：条件装配开关。前者"classpath 上有这个类才生效"，后者"你没自己定义这个 Bean 我才生效"。
**干什么**：这就是"约定优于配置"能工作的原因，也是**依赖冲突的根源**：classpath 上多了个类，可能就多启动一个 Tomcat。

#### Starter
**是什么**：一个"依赖套餐"——把某功能需要的所有 jar 打成一个 pom，再加自动配置。
**项目里**：`spring-boot-starter-web`、`spring-cloud-starter-gateway`、`spring-boot-starter-amqp`。

#### @SpringBootApplication
**是什么**：三个注解的组合：
- `@SpringBootConfiguration`（= `@Configuration`）
- `@EnableAutoConfiguration`（开启自动配置）
- `@ComponentScan`（扫描当前包及子包）

#### @ComponentScan
**是什么**：指定"去哪些包找 Bean"。
**项目里为什么每个启动类都要手写**：
```java
@ComponentScan(basePackages = {"com.zhuawa.shop.common", "com.zhuawa.shop.seckill"})
```
因为默认只扫启动类所在包（`com.zhuawa.shop.seckill`），而 `common` 在另一个包下，不写就注入失败。
**Go 对照**：忘了调 `common.Register()`。

### 4. Web 层：一个 HTTP 请求怎么进到你的方法

#### Controller
**是什么**：接收 HTTP 请求的类，方法对应一个接口。
**Go 对照**：`http.HandlerFunc`。

#### @RequestMapping / @GetMapping / @PostMapping
**是什么**：URL 与方法的绑定。类上写前缀，方法上写具体路径。
**项目里**：`@RequestMapping("/seckill")` + `@GetMapping("/list")` = 完整路径 `/seckill/list`。

#### @PathVariable / @RequestParam / @RequestBody
**是什么**：参数从哪来。
- `@PathVariable`：从**路径**里取，`/detail/{goodsId}` → 方法参数 `goodsId`
- `@RequestParam`：从 **URL query** 里取，`?userId=1&goodsId=2`
- `@RequestBody`：从 **请求体 JSON** 里反序列化

#### Servlet 栈 vs 响应式栈（Tomcat vs Netty）
**是什么**：两种 Web 运行时。
- **Servlet**（Tomcat）：一个请求占一个线程，阻塞式。业务服务都用它。
- **WebFlux**（Netty）：事件循环，少量线程处理大量连接，非阻塞。**Gateway 用的就是它。**
**为什么重要**：两套栈**不能混**。`spring-boot-starter-web` 和 `spring-boot-starter-gateway` 同时存在会冲突——这就是为什么 `gateway` 不能依赖 `common`（`common` 里带了 web starter）。

#### 拦截器（HandlerInterceptor）
**是什么**：Spring MVC 的钩子，在 Controller 方法执行**前后**插逻辑，能拿到 `HttpServletRequest`。
**项目里**：`AccessInterceptor` 在 `preHandle` 里解析 JWT、放入 ThreadLocal、校验 `@AccessLimit`；`afterCompletion` 里清理。
**Go 对照**：middleware，但它是框架级注册，只能拦 Controller。
**和 Filter 的区别**：Filter 是 Servlet 规范更外层的东西，连静态资源都拦；Interceptor 只拦 Controller 方法。

#### 参数解析器（HandlerMethodArgumentResolver）
**是什么**：决定"Controller 方法的这个参数，值从哪来"。
**项目里**：`UserArgumentResolver` 判断参数类型是 `LoginUser`，就从 `UserContext`（ThreadLocal）里取当前用户塞进去。
**效果**：Controller 里直接写 `LoginUser user` 就能拿到登录用户，不用每处都解析 token。
**Go 对照**：自己写个 `func(ctx context.Context) *User` 然后每个 handler 调一次；这里是框架自动调。

#### ThreadLocal
**是什么**：线程本地变量，每个线程一份副本，互不干扰。
**项目里**：`UserContext` 用它存当前请求的登录用户。因为 Servlet 模型下"一个请求 = 一个线程"，所以能安全传递。
**必须注意**：线程池会复用线程！所以 `afterCompletion` 里必须 `UserContext.clear()`，否则下一个请求会读到上一个用户（串号）。
**Go 对照**：`context.Context`。区别是 Go 显式传参，Java 这里靠线程隐式传递——所以更容易出错。

#### AOP（面向切面编程）
**是什么**：不改源码，在方法前后插入逻辑。实现方式是**动态代理**：容器给你的不是原对象，而是一个包了一层的代理对象。
**项目里**：`@Transactional` 就是 AOP。你在 `createOrder` 上加注解，实际调用时事务的 begin/commit/rollback 是代理帮你做的。
**副作用（重要）**：**同类内部自调用不走代理，注解失效**。这是 Java 事务最常见的事故。

#### 全局异常处理
**是什么**：`@RestControllerAdvice` + `@ExceptionHandler`，把抛出的异常统一转成 JSON 响应。
**项目里**：`GlobalExceptionHandler` 把 `GlobalException` 转成 `Result.error(CodeMsg)`。
**Go 对照**：统一 recover + 错误响应封装。

#### CORS（跨域资源共享）
**是什么**：浏览器的安全策略。页面在 `localhost:18004`，请求 `localhost:8081`，属于跨域，默认被浏览器拦。
**怎么解**：服务端响应头声明"我允许哪个源"。
**项目里**：`gateway/application.yml` 的 `globalcors`，只允许 `http://localhost:18004`。
**坑**：`allowCredentials: true`（允许带 cookie）时，`allowedOrigins` 不能写 `*`，必须写具体域名。

### 5. 微服务与 Spring Cloud

#### 微服务
**是什么**：按业务边界拆成多个可独立部署的小服务，各自有数据库，通过 HTTP/RPC 通信。
**对比单体**：单体一个进程一个库；微服务 N 个进程 N 个库，代价是"分布式复杂性"（网络失败、数据一致性、链路追踪）。

#### 服务注册与发现
**是什么**：服务启动时把自己的 `IP:端口` 登记到一个中心，调用方从这个中心查地址。
**为什么需要**：实例地址会变（扩容、重启、容器漂移），不能写死在配置里。
**Go 对照**：etcd / consul + `grpc-resolver`。

#### Eureka
**是什么**：Netflix 开源的服务注册中心，Spring Cloud 官方集成。
**怎么工作**：
1. 服务启动 → 向 Eureka 发送注册请求
2. 每 30 秒发一次**心跳**（续约）
3. 90 秒没心跳 → 从列表剔除
4. 调用方定时拉取服务列表，缓存在本地
**特点**：AP 优先（可用性 > 一致性），所以网络分区时可能拿到已下线的实例——需要客户端容错。
**项目里**：`eureka-server` 模块，`@EnableEurekaServer`；其他服务 `@EnableEurekaClient` + `eureka.client.service-url.defaultZone`。
**看板**：http://127.0.0.1:8761

#### 网关（API Gateway）
**是什么**：所有外部请求的统一入口，转发给内部服务。
**干什么**（四件事）：
1. **路由**：`/goods/**` → goods 服务
2. **鉴权**：统一校验 JWT，业务服务不用各写一遍
3. **限流**：挡住刷接口
4. **跨域/日志/灰度**：集中处理
**项目里**：`gateway` 模块，Spring Cloud Gateway（基于 WebFlux）。
**Go 对照**：nginx 反代 + 自写中间件。

#### 路由（Route）/ Predicate / Filter
**是什么**：Gateway 的三个概念。
```yaml
- id: zhuawa_shop_goods_route        # 路由名字
  uri: http://localhost:18001        # 转到哪
  predicates:                        # 什么条件匹配（断言）
    - Path=/goods/**
  filters:                           # 匹配后怎么加工
    - StripPrefix=1
```
- **Predicate（断言）**：匹配条件，除了 Path 还有 Host、Method、Header、时间等。
- **Filter（过滤器）**：改请求/响应，比如加 header、去前缀、限流。

#### StripPrefix
**是什么**：网关过滤器，去掉路径的前 N 段。
**项目里为什么需要**：
前端请求 `/seckill/seckill/list` → `StripPrefix=1` 去掉第一个 `seckill` → 服务收到 `/seckill/list` → 匹配 `@RequestMapping("/seckill") + @GetMapping("/list")`。
**所以前端基址是 `http://localhost:8081/seckill/seckill`**，看着重复但是对的（第一个是路由前缀，第二个是服务内路径）。

#### 负载均衡（Load Balancing）
**是什么**：一个服务有多个实例时，请求怎么分配（轮询、随机、加权）。
**两种模式**：
- **服务端**：nginx 那种，客户端只知道 nginx 地址
- **客户端**：调用方自己从实例列表里挑一个（Spring Cloud 默认这种）
**项目里**：`lb://order` 中的 `lb` 就是它，实现是 **Spring Cloud LoadBalancer**。

#### Ribbon
**是什么**：Netflix 的老负载均衡组件。
**注意**：**Spring Cloud 2020.0 已移除**。你在网上看到的老教程提到它，在这个项目里**不适用**。

#### OpenFeign（Feign）
**是什么**：**声明式 HTTP 客户端**。你只写接口 + 注解，不写实现，框架在运行时生成实现。
**解决什么问题**：没有 Feign，你得手写 URL 拼接、序列化、错误处理、服务发现——每个调用都要重复一遍。
**怎么用**（三步）：
```java
// 1. 定义接口（放在 xxx-service-client 模块）
@FeignClient(value = "goods")          // 服务名 = 对方的 spring.application.name
@RequestMapping("/goods")
public interface GoodsApi {
    @GetMapping("/get/{id}")
    Result<Goods> get(@PathVariable("id") Long id);
}

// 2. 调用方启动类开启
@EnableFeignClients(basePackages = {"com.zhuawa.shop.goods.api"})

// 3. 直接注入使用
@Autowired GoodsApi goodsApi;
Goods g = goodsApi.get(1L).getData();
```
**背后发生了什么**：拿 `goods` 去 Eureka 查实例 → 负载均衡选一个 → 拼出 `GET http://ip:18001/goods/get/1` → 发请求 → JSON 反序列化成 `Result<Goods>`。
**三个必须对齐的点**（不齐就 404 或反序列化失败）：
1. `@FeignClient("goods")` == 对方 `spring.application.name`
2. 接口 `@RequestMapping` + 方法映射 == 对方 Controller 的完整路径
3. 返回类型结构一致
**Go 对照**：手写的 client 封装（`func GetGoods(id int64) (*Goods, error)`），只是 Feign 帮你把 HTTP 细节全省了。

#### 声明式 vs 编程式
**是什么**：`声明式` = 说"我要什么"（写注解）；`编程式` = 说"怎么做"（写代码）。Feign、`@Transactional`、Gateway 路由都是声明式。
**好处**：代码短、意图清楚。**代价**：出问题时不知道内部发生了什么（"魔法"），排查要靠日志和源码。

#### 限流（Rate Limiting）
**是什么**：限制单位时间的请求数，超出直接拒绝。
**常见算法**：计数器、滑动窗口、漏桶、**令牌桶**。
**项目里**：Gateway 的 `RequestRateLimiter`，用 Redis 实现，按 IP 限流。
```yaml
redis-rate-limiter.replenishRate: 1   # 每秒放 1 个令牌（稳定速率）
redis-rate-limiter.burstCapacity: 5   # 桶容量 5（允许瞬时突发 5 个）
```

#### 令牌桶算法
**是什么**：一个桶，按固定速率往里放令牌，桶满了就丢弃；每个请求要取一个令牌，取不到就拒绝。
**效果**：既限制了**平均速率**（1/s），又允许**短时突发**（最多 5 个）。比"每秒最多 N 个"更平滑。

#### 熔断（Circuit Breaker）
**是什么**：下游服务持续失败时，**直接快速失败**，不再真发请求，避免请求堆积把自己也拖垮。
**类比**：电路保险丝。半开状态会试探性放几个请求过去，成功就恢复。
**降级（Fallback）**：熔断或失败时返回兜底结果（缓存值、默认值、友好提示）。
**项目里**：**没有实现**。`feign.hystrix.enabled: true` 是无效配置（见 Hystrix）。

#### Hystrix
**是什么**：Netflix 的熔断/隔离组件。
**关键事实**：**Spring Cloud 2020.0 已把它移除**。所以项目里那个配置项被 Spring 忽略了——不报错，但也不生效。
**现在用什么**：`spring-cloud-starter-circuitbreaker-resilience4j`，或阿里的 Sentinel。

#### 分布式事务
**是什么**：一个业务跨多个服务/多个数据库，要么全成功要么全失败。
**为什么难**：没有单个数据库的 `BEGIN/COMMIT` 能覆盖多个库。
**常见方案**：
- **2PC/XA**：强一致，性能差
- **TCC**：Try-Confirm-Cancel，业务层补偿
- **Saga**：一串本地事务 + 反向补偿
- **本地消息表 / 事务消息**：保证"本地操作"和"发消息"原子，靠消费端重试达到最终一致
- **Seata**：阿里开源的一站式框架
**项目里**：`order-service` 的 `genOrder` 跨了 goods/order/user 三个库，**没有分布式事务**（代码里留了 `//TODO`）。

#### 最终一致性
**是什么**：允许中间状态短暂不一致，但经过重试/补偿后最终对齐。
**项目里**：秒杀就是——Redis 扣了、MQ 里排着、DB 还没落，此时查询结果是"排队中"，最终会一致。

#### 幂等（Idempotency）
**是什么**：同一个请求执行一次和执行多次，结果相同。
**为什么必须**：MQ 会重复投递（至少一次语义），网络超时会重试。
**项目里三处**：
1. `order_seckill` 表的 `uk_user_goods` 唯一索引
2. 消费前查"是否已有订单"
3. Redis 的 `setnx` 标记

#### 削峰（削峰填谷）
**是什么**：瞬时高峰先写进队列，后端按自己的节奏消费，把"峰"摊平成"平"。
**项目里**：秒杀请求 → RabbitMQ → 消费者串行落库。

#### 缓存预热
**是什么**：系统启动时（或活动开始前）主动把热点数据加载进缓存，避免第一批请求打到数据库。
**项目里**：`SeckillController.init()` 上的 `@PostConstruct` —— Bean 初始化完成后执行一次，把库存写进 Redis。

### 6. 数据访问

#### MyBatis
**是什么**：Java 的 SQL 映射框架，属于"半自动 ORM"——**SQL 你自己写**，它负责把结果集映射成对象。
**为什么叫半自动**：Hibernate/JPA 是全自动（你不管 SQL），MyBatis 让你掌控 SQL，性能调优方便。
**Go 对照**：`sqlx` / `gorm` 的 Raw 模式。

#### Mapper
**是什么**：MyBatis 的 DAO 接口。方法上可以贴 SQL 注解，也可以由 XML 实现。
**项目里**：
```java
@Select("select * from order_seckill where user_id = #{userId} and goods_id = #{goodsId}")
OrderSeckill getOrderSeckill(...);
```
**注意**：**全项目没有任何 XML**，都是注解 SQL —— 所以 yml 里 `mapper-locations: classpath:mapper/*Mapper.xml` 是历史残留。

#### tk.mybatis（通用 Mapper）
**是什么**：在 MyBatis 上加了"通用 CRUD"，继承 `Mapper<T>` 就白得 `select/insert/updateByPrimaryKey/selectByExample`。
**项目里**：`GoodsDao extends Mapper<Goods>`，基础增删改查一行不用写。
**Go 对照**：`gorm` 的 `db.Create(&u)`。

#### ORM（对象关系映射）
**是什么**：数据库的行 ↔ Java 对象 的自动转换。
**命名映射**：`map-underscore-to-camel-case: true` 让 `stock_seckill`（库）自动对应 `stockSeckill`（Java 属性）。**没开这个，字段全是 null** —— 常见坑。

#### 连接池 / Druid
**是什么**：预先建好一批数据库连接反复复用，避免每次请求都 TCP 握手 + 认证。
**Druid**：阿里开源的连接池，带监控。
**项目里参数**：`maxActive: 1000`（最大连接）、`initialSize: 100`（启动就建 100 个）、`minIdle: 500`。
> 说明：`maxActive: 1000` 对单机 MySQL 偏大，生产环境通常 20~50。这是教学项目的夸张配置。

#### @Transactional
**是什么**：声明式事务。方法上加注解，方法内抛异常就回滚。
**怎么实现的**：AOP 代理，方法执行前 `begin`，正常返回 `commit`，抛 `RuntimeException` 则 `rollback`。
**三个坑**：
1. **同类自调用失效**（不走代理）
2. **默认只回滚 `RuntimeException`**，受检异常不回滚（要写 `rollbackFor = Exception.class`）
3. **方法必须是 `public`**

#### 行级锁
**是什么**：InnoDB 执行 `UPDATE ... WHERE id = ?` 时，锁住被修改的行，其他事务等它提交。
**项目里为什么安全**：`UPDATE goods_seckill SET stock_seckill = stock_seckill - 1 WHERE goods_id = ? AND stock_seckill > 0` —— 并发的两个事务会排队，第二个看到的已经是扣过的值，条件不满足则影响行数为 0。

#### 乐观锁 vs 悲观锁
- **悲观锁**：先锁住再操作（`SELECT ... FOR UPDATE`），冲突多时合适
- **乐观锁**：不加锁，更新时校验（`WHERE stock > 0` 或 `WHERE version = ?`），冲突少时性能好
**项目里**：秒杀用的是乐观策略 + 数据库原子更新。

#### 唯一索引
**是什么**：数据库层保证某列（或组合）不重复，插入重复直接报错。
**项目里**：`order_seckill` 的 `uk_user_goods(user_id, goods_id)` —— **一人一单的最后一道防线**，即使 Redis 挂了也不会重复下单。

### 7. 中间件

#### Redis
**是什么**：内存键值数据库，单线程执行命令（所以命令天然原子），QPS 十万级。
**项目里四处用**：
1. 库存预减（`DECR`）
2. 一人一单判重（`SETNX`）
3. 秒杀 path 存 60 秒
4. 网关限流（令牌桶）

#### StringRedisTemplate
**是什么**：Spring 封装的 Redis 客户端，key 和 value 都按字符串处理（相比 `RedisTemplate`，省掉序列化配置的麻烦）。
**项目里**：`RedisService` 包了一层，提供 `get/set/setIfAbsent/decr/incr`。

#### DECR / INCR
**是什么**：原子自减/自增 1。
**为什么必须用它**：`get` 再 `set` 是两步，并发下会超卖；`DECR` 是 Redis 内部一步完成，返回减后的值。
**Go 对照**：`redis.Decr(ctx, key).Val()`。

#### SETNX
**是什么**：SET if Not eXists —— key 不存在才设置成功，返回 true；已存在返回 false。
**干什么**：分布式锁 / 判重。项目里 `seckill:orderMark:{userId}:{goodsId}` 设置成功才允许下单。

#### TTL（Time To Live）
**是什么**：key 的过期时间，到点自动删除。
**项目里**：path 60 秒、判重标记 3600 秒。

#### 缓存穿透 / 击穿 / 雪崩
- **穿透**：查一个**不存在**的数据，每次都打到数据库（缓存永远不命中）→ 解法：缓存空值、布隆过滤器
- **击穿**：某个**热点 key 过期**瞬间，大量请求同时打到数据库 → 解法：互斥锁、逻辑过期
- **雪崩**：**大批 key 同时过期**或 Redis 挂掉 → 解法：过期时间加随机、集群、限流降级
**项目里**：用 `seckillOverMap` 内存标记 + `goodsOver` 标记，算是对"穿透"的一种防御。

#### RabbitMQ
**是什么**：消息队列，实现 AMQP 协议。生产者发消息到队列，消费者异步取。
**干什么**：异步解耦、削峰、最终一致。
**核心概念**：
- **Producer** 生产者（`MQSender`）
- **Queue** 队列（`seckill.queue`、`canal.queue`）
- **Consumer** 消费者（`@RabbitListener` 标的方法）
- **Exchange** 交换机（决定消息投到哪个队列）

#### Exchange / Binding / Routing Key
**是什么**：生产者不直接发到队列，而是发给 **Exchange**，Exchange 按 **Binding** 规则（routing key）转发到队列。
**四种类型**：Direct（精确匹配）、Topic（通配符）、Fanout（广播）、Headers。
**项目里**：`amqpTemplate.convertAndSend(QUEUE_NAME, msg)` —— 只传队列名，走默认 Exchange，routing key 就是队列名。**这是最简单的用法**，教学项目够用，生产里通常显式声明 Exchange。

#### ACK（消息确认）
**是什么**：消费者处理完告诉 MQ"我处理好了，可以删了"。
**两种模式**：
- **自动 ACK**：消息一投递就删，消费失败会丢消息
- **手动 ACK**：处理完才确认，失败可重回队列
**项目里**：Spring AMQP 默认是**自动 ACK + 异常时重新入队**（`default-requeue-rejected: true`），所以 `createOrder` 抛异常会让消息重投——这就是"库存扣不动自动重试"的机制。

#### prefetch（预取数量）
**是什么**：消费者一次从队列预取多少条消息。
**项目里**：`prefetch: 1` —— 处理完一条才取下一条。配合 `concurrency: 10`（10 个并发消费者），既保证顺序可控，又有并发能力。

#### 死信队列（DLQ）
**是什么**：消费失败达到最大重试次数的消息，被转到另一个队列，避免无限重试卡死。
**项目里**：**没有配置**。所以一条坏消息（比如持续抛异常的订单）会被无限重投 —— 是个隐患。

#### Canal
**是什么**：阿里开源的工具，**伪装成 MySQL 的从库**，订阅 binlog，把数据变更推给你。
**干什么**："数据库一改，我就知道"。项目用它同步商品到 ES。
**为什么不用业务代码里发消息**：不用改业务代码、不侵入、也覆盖了手工改库的情况。
**工作原理**：MySQL 主从复制协议 → Canal Server 解析 binlog → 转成结构化事件 → 推给客户端。

#### binlog
**是什么**：MySQL 的二进制日志，记录所有数据变更。主从复制就靠它。

#### Elasticsearch（ES）
**是什么**：基于 Lucene 的搜索引擎，专长全文检索和聚合分析。
**为什么不用 MySQL 的 `like '%关键词%'`**：`like` 前置通配符**用不上索引**，全表扫描；ES 用**倒排索引**，毫秒级。
**项目里**：`search-service` 用 Spring Data ES，`goods-service` 也配了 ES（但没实际用）。
**版本注意**：项目用 ES 7.12 + `spring-boot-starter-data-elasticsearch`，通过 **9300 端口**（Transport 协议）连接。ES 8 已废弃该端口。

#### 倒排索引
**是什么**：从"文档 → 词"反过来建"词 → 文档列表"的索引。
**举例**：搜"手机"，直接查到含"手机"的文档 id 列表，不用扫全表。

#### 分词器（Analyzer）/ ik
**是什么**：把一句话切成词。"中国共产党" → `中国 / 共产党`（ik_smart）或 `中国 / 国人 / 共产党`（ik_max_word）。
**为什么需要**：中文没空格，搜索引擎必须自己切词才能建索引。
**ik**：最常用的中文分词插件。

#### DSL
**是什么**：ES 的 JSON 查询语言。README 里那一大段 `GET /user/_search { "query": ... }` 就是。

#### Kibana
**是什么**：ES 的可视化管理台，能执行 DSL、看索引、做图表。

### 8. 安全与认证

#### JWT（JSON Web Token）
**是什么**：一种自包含的令牌，三段用点分隔：`header.payload.signature`。
```
eyJhbGciOiJIUzI1NiJ9 . eyJpZCI6MSwibW9iaWxlIjoiMTM4In0 . 4pcPyMD09olPSyXn...
      header                  payload（用户信息）              signature（签名）
```
**解决什么问题**：传统 Session 要把登录态存在服务端（还要解决多实例共享）。JWT 把状态放在客户端，服务端只验签名——**无状态**，天然适合微服务。
**关键点**：payload 只是 **Base64 编码，不是加密**！任何人解出来都能看到内容。所以**别放密码**，只放 id/昵称这类非敏感信息。
**签名算法**：`HS256` = HMAC-SHA256，用同一个密钥签和验（对称）。项目里密钥硬编码 `1a2b3c4d`。

#### Claims
**是什么**：JWT payload 里的键值对集合，`Jwts.parser().parseClaimsJws(token).getBody()` 拿到的就是它。
**项目里**：`subject` 存的是用户信息 JSON（`{"id":1,"mobile":"...","nickname":"..."}`）。

#### Cookie
**是什么**：浏览器存的 KV，**同域请求会自动带上**。
**项目里**：登录成功把 JWT 写进 `zhuawa-shop-token` cookie，`setPath("/")` 让它对整个站点生效。
**和 header 的关系**：项目里三种取 token 的方式都支持——header、cookie、URL 参数（`AuthFilter` 里依次尝试）。生产环境**不要**支持 URL 参数，token 会留在日志里。

#### MD5 加盐
**是什么**：密码不存明文，存 `MD5(密码 + 随机盐)`。
**为什么加盐**：不加盐的话，同样的密码哈希相同，彩虹表一撞就破。
**项目里**：`MD5Util.formPassToDBPass(formPass, saltDB)` —— 前端先 MD5 一次（`md5.min.js`），后端再加盐 MD5 一次。

#### 鉴权 vs 认证
- **认证（Authentication）**：你是谁 —— 登录
- **鉴权（Authorization）**：你能干什么 —— 权限校验
**项目里**：`AuthFilter` 只做认证（token 有效就放行），**没有做权限控制**（谁都能访问任何接口）。

## 第二部分：本项目自造的概念

这些名词**不是通用术语**，只在这个项目里成立，看代码时容易误以为是标准概念。

| 名词 | 是什么 | 在哪 |
|---|---|---|
| `Result<T>` | 统一响应体 `{code, msg, data}`，`code=0` 表示成功 | `common/result/Result.java` |
| `CodeMsg` | 错误码枚举（其实是静态常量对象），如 `500501 不能重复秒杀` | `common/result/CodeMsg.java` |

| `LoginUser` | 从 JWT payload 反序列化出来的登录用户对象 | `common/access/LoginUser.java` |
| `UserContext` | 用 ThreadLocal 存 `LoginUser`，一次请求内随处可取 | `common/access/UserContext.java` |
| `@AccessLimit` | 自定义注解，标在方法上表示"这个接口要登录" | `common/access/AccessLimit.java` |
| 秒杀 `path` | MD5 随机串，60 秒有效，让接口地址动态化，防脚本预拼 URL | `SeckillService.createSeckillPath` |
| 内存标记 `seckillOverMap` | JVM 本地 `ConcurrentHashMap`，记录"该商品已售罄" | `SeckillController` |

| 一人一单 | 同一用户同一商品只能下一单 | Redis SETNX + `uk_user_goods` 索引 |
| `*-service-client` 模块 | 只放接口和 POJO 的"契约包"，供别的服务 Feign 调用 | 如 `goods-service-client` |

## 第三部分：最容易混淆的几组

### ① VO / DTO / Entity / POJO / Model
| 名字 | 含义 | 项目里 |
|---|---|---|
| **POJO** | 统称：只有字段 + getter/setter 的普通类 | 所有 model 都是 |
| **Entity** | 和数据库表一一对应的对象 | `Goods`、`Orders`、`User` |
| **DTO** | 数据传输对象，跨层/跨服务传数据用 | `OrdersParam`（前端传进来的） |
| **VO** | 视图对象，专门给前端展示用（可能拼了多个表） | `OrderVO`、`SeckillDetailVo`、`CartItemVO` |
| **Model** | 项目里当"实体包名"用，比较随意 | `com.zhuawa.shop.goods.model` |

**一句话**：Entity 对着表，DTO 对着入参，VO 对着出参。

### ② Filter / Interceptor / GlobalFilter / AOP
| 名字 | 属于 | 能拦什么 | 项目里 |
|---|---|---|---|
| **Filter** | Servlet 规范 | 所有请求（含静态资源） | 未使用 |
| **Interceptor** | Spring MVC | 只拦 Controller 方法 | `AccessInterceptor` |
| **GlobalFilter** | Spring Cloud Gateway | 网关转发的所有请求 | `AuthFilter` |
| **AOP** | Spring 代理 | 任意 Bean 方法 | `@Transactional` |

**执行顺序**：Filter → Interceptor.preHandle → AOP → Controller → Interceptor.afterCompletion

### ③ 熔断 / 降级 / 限流 / 幂等 / 削峰
| 名词 | 一句话 | 项目里 |
|---|---|---|
| **限流** | 太多请求，直接拒掉一部分 | ✅ 网关令牌桶（但只配了 goods 路由） |
| **熔断** | 下游一直失败，就不再调它，快速失败 | ❌ 无（Hystrix 已失效） |
| **降级** | 失败时返回兜底数据 | ❌ 无 |
| **幂等** | 重复请求不产生重复结果 | ✅ 三处（SETNX / 唯一索引 / 消费前查单） |
| **削峰** | 高峰先入队，后端慢慢消费 | ✅ RabbitMQ |

### ④ 服务发现 / 负载均衡 / 网关路由
- **服务发现**：地址从哪来（Eureka）
- **负载均衡**：多个地址选哪个（LoadBalancer，`lb://`）
- **网关路由**：外部请求怎么进来的（Gateway Route）
三个是**串联**的：请求进网关 → 路由匹配 → `lb://` → 查 Eureka → 选实例 → 转发。

### ⑤ 强一致 / 最终一致
- **强一致**：任何时刻查到的都一样（单库事务就是）
- **最终一致**：中间可以不一致，但最终对齐（秒杀：Redis 扣了 → MQ 排队 → DB 落库）
**微服务里 90% 的场景只能做到最终一致**，因为跨库没有共享事务。
