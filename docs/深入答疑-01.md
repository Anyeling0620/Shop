## Q1. 项目里熔断是怎么做到快速失败的？

### 结论：**项目里没有熔断。**

### 先解释熔断是什么

熔断（Circuit Breaker）是**调用方**的一种自我保护机制。

场景：你调下游服务，下游卡住了（不返回、也不报错）。如果不做处理，你的线程会一直等，等到超时。并发一多，线程池被占满，你这个服务也挂了 —— 这叫**雪崩**。

熔断器像一个开关，有三种状态：

| 状态 | 行为 |
|---|---|
| **关闭 Closed** | 正常调用，同时统计失败率 |
| **打开 Open** | **不再发起真实调用**，直接返回失败/兜底值。这就是"快速失败"——省掉了整个网络等待 |
| **半开 Half-Open** | 打开一段时间后，放少量请求试探；成功则回到关闭，失败则继续打开 |

"快速失败"的快，来源只有一个：**不发起网络请求**。不是"调得快"，是"根本不调"。

### 项目里的实际情况

三条证据：

1. **依赖里没有任何熔断组件。** 全仓库 `pom.xml` 搜 `hystrix|sentinel|circuitbreaker|resilience4j`，零命中。
2. **所有服务 yml 里都有 `feign.hystrix.enabled: true`，但这个配置没人读。** Spring Cloud 2020.0 已经把 Netflix Hystrix 移出，这个 key 不再是任何配置类的字段。写了不报错，也不生效——属于**静默失效**。
3. **`gateway/pom.xml` 里 hystrix 依赖是注释掉的**，Java 代码里搜 `Hystrix|Sentinel|CircuitBreaker|Fallback` 也是零命中。

### 所以现在失败时是什么表现

Feign 的默认超时（Spring Cloud OpenFeign）：**连接超时 10 秒，读超时 60 秒**。

- 下游**进程挂了** → TCP 连接被拒绝 → 立刻抛 `ConnectException`。这种确实"快"，但这是操作系统给的，不是熔断。
- 下游**卡住不响应**（比如数据库锁等待、GC 停顿）→ 要等 **60 秒**才失败。这 60 秒里 Tomcat 线程一直被占着。默认 200 个线程，200 个请求就能把服务打死。

**结论：项目只会在"连不上"时快，在"响应慢"时会被拖死。而这恰恰是熔断要解决的场景。**

### 想加上，最小改法

**方案 A：官方推荐（Resilience4j）**

```xml
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-circuitbreaker-resilience4j</artifactId>
</dependency>
```

```yaml
resilience4j:
  circuitbreaker:
    configs:
      default:
        slidingWindowSize: 10                 # 统计最近 10 次调用
        minimumNumberOfCalls: 5               # 至少 5 次才开始算失败率
        failureRateThreshold: 50              # 失败率 > 50% 就打开
        waitDurationInOpenState: 10s          # 打开 10 秒后转半开
        permittedNumberOfCallsInHalfOpenState: 3
```

配合 Feign 的兜底类：

```java
@FeignClient(value = "goods", fallbackFactory = GoodsApiFallbackFactory.class)
public interface GoodsApi { ... }

@Component
public class GoodsApiFallbackFactory implements FallbackFactory<GoodsApi> {
    @Override
    public GoodsApi create(Throwable cause) {
        return new GoodsApi() {
            @Override public Result<Goods> get(Long id) {
                // 兜底：返回错误码而不是抛异常，调用方可以降级展示
                return Result.error(CodeMsg.SERVER_ERROR);
            }
            // 其余方法同样实现
        };
    }
}
```

> `fallback` 和 `fallbackFactory` 的区别：前者拿不到异常原因，后者能拿到 `Throwable`，便于区分"超时"还是"业务错误"。推荐用 factory。

**方案 B：Sentinel**（带控制台，见 Q2）

**方案 C：只做超时 + 重试**（成本最低，能止血但治不了雪崩）

```yaml
feign:
  client:
    config:
      default:
        connectTimeout: 1000     # 1 秒
        readTimeout: 2000        # 2 秒
```

> 注意：超时设短只是让失败变快，**不会阻止请求继续打过来**。真正的熔断是在下游已经被判定为"病态"后，直接拒绝。

**方案 D：网关层熔断**（在入口就挡住）

```yaml
filters:
  - name: CircuitBreaker
    args:
      name: goodsCB
      fallbackUri: forward:/fallback
```

需要 `spring-cloud-starter-circuitbreaker-reactor-resilience4j`。

## Q2. Netflix 和 Sentinel 是什么？

### Netflix OSS：一套"微服务零件库"

Netflix（奈飞）在 2011-2015 年把自己的微服务基础设施开源了，叫 **Netflix OSS**。Spring Cloud 早期（2015-2019）把它们逐个包装成 `spring-cloud-starter-netflix-*`：

| 组件 | 作用 | 现状 |
|---|---|---|
| **Eureka** | 服务注册与发现 | 仍在用（本项目在用），进入维护模式 |
| **Ribbon** | 客户端负载均衡 | **2020.0 已移除** |
| **Hystrix** | 熔断、线程隔离、降级 | **2020.0 已移除**（2018 年 Netflix 宣布停止开发） |
| **Zuul 1** | 网关 | **已移除**（被 Spring Cloud Gateway 替代） |
| **Archaius** | 配置管理 | 已移除 |
| **Turbine** | 熔断监控数据聚合 | 已移除 |

**为什么全退了**：Netflix 自己不再维护（Hystrix 最后版本 2018 年），Spring 官方也不想绑死在一家公司的实现上，于是自己做了抽象层：`spring-cloud-loadbalancer`（替代 Ribbon）、`spring-cloud-circuitbreaker`（替代 Hystrix）、`spring-cloud-gateway`（替代 Zuul）。

**对本项目的意义**：
- `eureka-server` 是 Netflix 的 —— 还能用
- `feign.hystrix.enabled: true` 是给 Netflix Hystrix 的 —— 已经没这个组件了
- `lb://order` 背后是 Spring 自己的 LoadBalancer，**不是 Ribbon**

### Sentinel：阿里开源的"流量治理"组件

**是什么**：阿里巴巴 2018 年开源的流量控制与熔断降级组件，前身是阿里内部用了近十年的组件。

**和 Hystrix 的区别——Sentinel 管得更宽**：

| 能力 | Hystrix | Sentinel |
|---|---|---|
| 熔断降级 | ✅ | ✅ |
| 限流（QPS / 线程数） | ❌ | ✅ |
| 热点参数限流 | ❌ | ✅ |
| 系统自适应保护（按 load / RT） | ❌ | ✅ |
| 授权规则（黑白名单） | ❌ | ✅ |
| 实时监控控制台 | 需 Turbine + Dashboard | ✅ 自带 Dashboard |
| 维护状态 | 停止 | 活跃 |
| 支持框架 | Java | Java / Go / C++ / Rust，20+ 框架 |

**怎么接**（Spring Cloud Alibaba）：

```xml
<dependency>
    <groupId>com.alibaba.cloud</groupId>
    <artifactId>spring-cloud-starter-alibaba-sentinel</artifactId>
</dependency>
```

然后在 Sentinel Dashboard 上可视化配规则（QPS 阈值、熔断策略），规则可持久化到 Nacos。

**Go 生态类比**：
- Netflix 那套 → `hystrix-go`（同样已停维护）
- Sentinel → `alibaba/sentinel-golang`（活跃）
- 现在 Go 里更常用 → `sony/gobreaker`、`resilience4go`

### 三者怎么选（如果这个项目要补）

| 场景 | 选择 |
|---|---|
| 只想给 Feign 加个兜底、不折腾 | Resilience4j（Spring 官方，纯库，无额外部署） |
| 要控制台、要动态改规则、要限流 | Sentinel（需部署 Dashboard） |
| 生产环境、要可观测 | Sentinel 或 Resilience4j + Micrometer |

## Q3. 深入理解 tk.mybatis

### 它是什么

**tk.mybatis**（现在正式名叫 **MyBatis Mapper**，作者 abel533）是 MyBatis 的**增强插件**。核心价值一句话：**接口继承 `Mapper<T>`，就白得一套通用 CRUD 方法，不用写 SQL、不用写 XML。**

Go 类比：`gorm` 的 `db.Create(&user)` / `db.First(&user, 1)` —— 你不用为每张表写 insert/select。

### 它解决什么问题

MyBatis 原生：每张表要手写 `insert / selectById / selectAll / updateById / deleteById`，10 张表就是 50 个方法与 SQL。

用 tk.mybatis：
```java
public interface GoodsDao extends Mapper<Goods> {
    // 空的！但已经拥有 selectByPrimaryKey / insert / updateByPrimaryKey ...
}
```

### 原理（理解了这段，所有"魔法"都清楚了）

MyBatis 执行一个方法，靠的是找到对应的 `MappedStatement`（一条 SQL 的定义）。原生 MyBatis 从 XML 或注解里读。

tk.mybatis 的做法：在启动扫描 Mapper 接口时，**动态地把一批 `MappedStatement` 注册进 MyBatis 配置**。生成规则是：

- 表名 ← 实体类名驼峰转下划线（`Orders` → `orders`，`CartItem` → `cart_item`），或 `@Table(name=...)` 指定
- 列名 ← 字段名驼峰转下划线（`userId` → `user_id`），或 `@Column(name=...)` 指定
- 主键 ← `@Id` 标注的字段
- 自增 ← `@GeneratedValue(strategy = GenerationType.IDENTITY)`

所以 `goodsDao.selectByPrimaryKey(1L)` 实际执行的是：
```sql
SELECT id, name, price, stock, image, brand_id, ... FROM goods WHERE id = 1
```

> ⚠️ 本项目实体类上贴的是 `javax.persistence.*`（`@Id` / `@Column` / `@GeneratedValue`）—— 这是 **JPA 的注解**，但项目**没有引入 JPA 依赖**。tk.mybatis 只是复用了这套注解当元数据。看到 `javax.persistence` 不要以为用了 Hibernate。

### 项目里的实际用法（逐个）

**第一类：纯继承，一行代码没有（8 个）**

`BrandDao`、`CategoryDao`、`CategoryBrandDao`、`ParamDao`、`SpecsDao`、`CartItemDao`、`OrderItemDao`、`UserDao`：

```java
public interface UserDao extends Mapper<User> { }
```

`UserService` 里就直接用了：
```java
userDao.selectOne(user);                      // 按字段条件查一条
userDao.selectByPrimaryKey(id);               // 按主键查
userDao.insertSelective(u);                   // 插入（忽略 null 字段）
userDao.updateByPrimaryKeySelective(user);    // 按主键更新（只更新非 null 字段）
```

**第二类：继承 + 自己加一条 SQL（2 个）**

```java
// GoodsDao：加一个原子扣库存
@Update("update goods set stock=stock-#{num} where id=#{goodsId} and stock>=#{num}")
int decrStock(@Param("num") int num, @Param("goodsId") long goodsId);

// OrdersDao：加一个查 VO（联表结果不是单表实体）
@Select("select * from orders where id=#{id}")
OrderVO selectVOById(@Param("id") long id);
```

**第三类：完全不用 tk（2 处）**
- `seckill-service` 的 `OrderDao` / `SeckillGoodsDao`：纯注解 SQL
- `search-service` 的 `GoodsEsDao`：`ElasticsearchRepository`（Spring Data ES，另一套体系）

### `insert` 和 `insertSelective` 的区别（必须记住）

| 方法 | 生成的 SQL | 风险 |
|---|---|---|
| `insert` | `INSERT INTO t (a,b,c) VALUES (?,?,?)` | 字段为 null 也会写进去，把数据库默认值覆盖成 null |
| `insertSelective` | 只包含非 null 字段的 `<script>` 动态 SQL | 安全 |

同理 `updateByPrimaryKey` vs `updateByPrimaryKeySelective`：前者会把所有字段都更新（未设置的变 null），后者只更新你设过的。

**项目里到处用 Selective，就是正确做法。**

### `Example` 条件构造器

`OrderService.genOrder` 里删购物车用的：

```java
Example example = new Example(CartItem.class);
Example.Criteria criteria = example.createCriteria();
for (long cartItemId : ordersParam.getCartItemIds()) {
    ...
    criteria.orEqualTo("id", cartItemId);   // 循环拼 OR id=?
}
cartItemDao.deleteByExample(example);        // → DELETE FROM cart_item WHERE (id = ? OR id = ? ...)
```

作用：不用写 XML 就能拼动态 `WHERE`。Go 里对应 `gorm` 的 `db.Where("id IN ?", ids).Delete(&CartItem{})`。

### 五个坑

1. **实体必须有 `@Id`**，否则 `selectByPrimaryKey` 系列全部失效（启动时不报错，运行时才炸）。
2. **表名推不出来时用 `@Table(name="...")`**。默认驼峰转下划线，遇到复数或带前缀的表名会错。
3. **非数据库字段要标 `@Transient`**，否则会被拼进 SQL 导致 `Unknown column`。
4. **别和 MyBatis-Plus 混用**。MP 是另一个同类库（国内更流行、功能更多），注解是 `@TableName` / `@TableId`，两套不能同时用。
5. **版本耦合**。项目用的是 `tk.mybatis:mapper-spring-boot-starter:2.0.4` + `mybatis-spring-boot-starter:1.3.1`（MyBatis 3.4.x）。升 MyBatis 到 3.5+ 可能出现反射/接口签名不兼容。

## Q4. 项目里用了 ORM 吗？

### 结论：用了**半自动 ORM**（SQL Mapper），**没有**用全自动 ORM（JPA / Hibernate）。

### 先把"ORM"这个词拆开

| 层次 | 代表 | SQL 谁写 | 结果映射谁做 |
|---|---|---|---|
| 全自动 ORM | JPA / Hibernate | 框架生成 | 框架 |
| **半自动 ORM（SQL Mapper）** | **MyBatis** | **你写** | 框架 |
| 纯 JDBC | `java.sql.*` | 你写 | 你写 |

ORM = Object Relational Mapping，对象关系映射。核心就一件事：**数据库的行 ↔ Java 对象**。只要做了这件事，就算 ORM，区别只在"SQL 由谁生成"。

### 项目里的四处证据

1. **MyBatis 做映射**：`GoodsDao.decrStock` 的 `@Update`，`SeckillGoodsDao` 的联表查询，都是你写 SQL、框架把 `ResultSet` 映射成对象。
2. **`map-underscore-to-camel-case: true`**：这是 ORM 的典型配置——`stock_seckill`（库）自动对应 `stockSeckill`（Java）。没开这个，字段全是 null。
3. **tk.mybatis 的 `Mapper<T>`**：这部分 SQL 是框架生成的，**接近全自动 ORM** 的体验。所以准确说法是"两者混合"。
4. **`javax.persistence` 注解不是 JPA**：只是被 tk.mybatis 借用了。可以验证：全仓库 `pom.xml` 里没有 `spring-boot-starter-data-jpa` 或 `hibernate-core`。

### 顺便发现一个真实问题（和你问的 ORM 直接相关）

映射不一致会导致运行时报错。看 `SeckillGoodsDao`：

```sql
select g.id as goods_id, g.name, g.title, g.img, g.detail, g.price, g.stock, ...
from goods_seckill gs left join goods g on gs.goods_id = g.id
```

它查了 `g.title`、`g.img`、`g.detail`。

但 `Goods` 实体（`goods-service-client`）里只有：`name / price / stock / image / brandId / categoryId / ...` —— **没有 `title`、`img`、`detail`**。

而且 `sql/goods_table.sql` 里**根本没有 `goods` 表的建表语句**（只有 `brand / category / category_brand / specs / param / template` 六张）。

**结论**：秒杀服务假设的 `goods` 表结构，和商品服务的实体定义**不是同一个 schema**。这段 SQL 跑起来会 `Unknown column 'g.title'`。

这是"没有统一 schema 管理"的典型后果：两个服务各自假设表结构，靠人肉对齐，一定会漂移。

## Q5. Druid 怎么用？怎么监控？

### Druid 是什么

阿里巴巴开源的**数据库连接池**（也能当监控和 SQL 防火墙用）。

**连接池**要解决什么：数据库连接是 TCP + 认证，建立一次要几十毫秒。如果每个请求都新建连接，QPS 上不去。连接池预热一批连接反复复用。

**Druid 相比 HikariCP**（Spring Boot 默认）：HikariCP 更快更简单；Druid 胜在**自带监控面板、SQL 防火墙、慢 SQL 统计**。

### 项目里的实际情况（这里和直觉不一样，重点）

**依赖**：`com.alibaba:druid:1.1.10`（裸 jar）——**不是** `druid-spring-boot-starter`。

**yml 写的**：
```yaml
spring:
  datasource:
    type: com.alibaba.druid.pool.DruidDataSource
    filters: stat
    maxActive: 1000
    initialSize: 100
    minIdle: 500
    maxWait: 60000
    ...
```

**问题：这些池参数大概率一个都没生效。**

原因：Spring Boot 2.x 的 `DataSourceProperties` 只绑定这 5 个 key：
`url`、`username`、`password`、`driver-class-name`、`type`。

其余 `maxActive`、`initialSize`、`filters`、`minIdle`……**在这个类里根本没有对应字段，会被静默忽略**（不报错，这是最坑的地方）。Druid 只能用**自己的默认值**：`initialSize=0`、`maxActive=8`、`filters` 为空。

**所以现在实际状态是**：
- 连接池最大 8 个连接（不是 1000）
- `filters: stat` 没被应用 → **没有采集任何统计**
- 没有任何 `StatViewServlet` / `WebStatFilter` 注册（全仓库 Java 搜不到这两个类）→ **没有监控页面**

### 让配置真正生效（两条路）

**方案 A：换成 starter（改动小，推荐）**

```xml
<dependency>
    <groupId>com.alibaba</groupId>
    <artifactId>druid-spring-boot-starter</artifactId>
    <version>1.1.10</version>
</dependency>
```

yml 改为 `spring.datasource.druid.*`：

```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/goods?...
    username: root
    password: 12345678
    druid:
      initial-size: 5
      min-idle: 5
      max-active: 20
      max-wait: 60000
      validation-query: select 1
      test-while-idle: true
      filters: stat,wall,slf4j
      stat-view-servlet:
        enabled: true
        url-pattern: /druid/*
        login-username: admin
        login-password: admin123
        reset-enable: false
      web-stat-filter:
        enabled: true
        url-pattern: /*
        exclusions: "*.js,*.css,/druid/*"
```

**方案 B：保留裸 jar，手写配置类**（不改依赖）

```java
@Configuration
public class DruidConfig {

    /** 关键：用 @ConfigurationProperties 把 spring.datasource.* 绑到 DruidDataSource */
    @Bean
    @ConfigurationProperties("spring.datasource")
    public DataSource dataSource() {
        return new DruidDataSource();
    }

    /** 监控页面： /druid/index.html */
    @Bean
    public ServletRegistrationBean<StatViewServlet> statViewServlet() {
        StatViewServlet servlet = new StatViewServlet();
        ServletRegistrationBean<StatViewServlet> bean =
                new ServletRegistrationBean<>(servlet, "/druid/*");
        bean.addInitParameter("loginUsername", "admin");
        bean.addInitParameter("loginPassword", "admin123");
        bean.addInitParameter("resetEnable", "false");   // 生产必须 false
        return bean;
    }

    /** 采集 Web 请求与 SQL 的关联数据 */
    @Bean
    public FilterRegistrationBean<WebStatFilter> webStatFilter() {
        FilterRegistrationBean<WebStatFilter> bean =
                new FilterRegistrationBean<>(new WebStatFilter());
        bean.addUrlPatterns("/*");
        bean.addInitParameter("exclusions", "*.js,*.css,/druid/*");
        return bean;
    }
}
```

> 这段代码只需要加在需要监控的服务（goods / order / user / seckill 各一份，或抽到 common —— 但 gateway 不能依赖 common）。
> `@ConfigurationProperties("spring.datasource")` 是让 `maxActive` 等参数真正绑上去的关键；`type` 这个 key 没有对应 setter，会被忽略，不影响。

### 监控页能看什么

访问 `http://localhost:18001/druid/index.html`：

| 面板 | 看什么 |
|---|---|
| 数据源 | 当前连接数、活跃数、等待线程数、池命中率 |
| **SQL 监控** | 每条 SQL 的执行次数、平均耗时、最慢耗时、并发数、执行堆栈 |
| SQL 防火墙 | 拦截可疑语句（`wall` filter） |
| URI 监控 | 每个接口的 QPS、耗时、JDBC 执行次数 |
| Session 监控 | 会话数 |

**注意**：SQL 监控有内存开销，`spring.datasource.druid.filter.stat.log-slow-sql` 可以只记慢 SQL。生产环境务必改默认密码 + 加 IP 白名单，别暴露到公网（`allow` 参数）。

**如果不想要监控，只想要连接池，建议直接换 HikariCP**（Spring Boot 默认，性能更好，零配置）。

## Q6. `RedisService` 是怎么"包了一层"的？

### 先解释被包的是什么

`StringRedisTemplate` 是 Spring Data Redis 提供的 Redis 客户端封装。相比 `RedisTemplate`，它把 key 和 value 都固定为 `String`，省掉了序列化器的配置（`RedisTemplate` 默认用 JDK 序列化，存进去的东西在 redis-cli 里看是一堆乱码）。

Go 里对应：`redis.Client`（go-redis）。

### 封装的意义

`RedisService` 做三件事：

1. **收敛 API**：项目只需要 8 个操作，就不暴露 100 个方法
2. **统一返回类型**：把 `Boolean`/`Long` 统一成 `boolean`/`long`，调用方不用处理 `null`
3. **便于替换和测试**：以后换 Lettuce / Jedis / 加本地缓存，只改这一个类；单测时 mock 它比 mock `StringRedisTemplate` 简单

Go 里这就是"repository 接口"的常规做法。

### 逐方法解释

```java
@Service
public class RedisService {

    @Autowired
    StringRedisTemplate redisTemplate;   // Spring 自动注入，已在 application.yml 配好连接
```

**`get`**
```java
public String get(String key) {
    return redisTemplate.opsForValue().get(key);   // GET key
}
```
`opsForValue()` 是"操作字符串类型"的入口（Redis 还有 `opsForHash()`、`opsForList()`、`opsForSet()`、`opsForZSet()`）。不存在返回 `null`。

**`set`（无过期）**
```java
public void set(String key, String value) {        // SET key value
    redisTemplate.opsForValue().set(key, value);
}
```

**`set`（带过期）**
```java
public void set(String key, String value, long expireSeconds) {
    redisTemplate.opsForValue().set(key, value, expireSeconds, TimeUnit.SECONDS);  // SET key value EX 60
}
```
项目里用于：秒杀 path 存 60 秒、结果缓存。

**`setIfAbsent`（判重/分布式锁的基础）**
```java
public boolean setIfAbsent(String key, String value, long expireSeconds) {
    Boolean ok = redisTemplate.opsForValue()
            .setIfAbsent(key, value, expireSeconds, TimeUnit.SECONDS);
    return Boolean.TRUE.equals(ok);   // 防 NPE
}
```
语义：**key 不存在才设置成功**，等价 `SET key value NX EX 60`，返回 `true`；已存在返回 `false`。

**这里有个重要的正确性细节**：很多老教程教你这样加锁：
```java
if (redis.setnx(key, "1")) {   // 第一步：加锁
    redis.expire(key, 60);      // 第二步：设过期
}
```
如果第一步成功、第二步之前进程崩了，锁就**永不过期** → 死锁。

项目用的 `setIfAbsent(key, value, timeout, unit)` 是 **Redis 2.6.12+ 的 `SET ... NX EX`，两条命令合成一条，原子执行**，没有这个窗口。这是正确写法。

**`decr`**
```java
public long decr(String key) {
    Long v = redisTemplate.opsForValue().decrement(key);   // DECR key
    return v == null ? 0L : v;
}
```
语义：原子减 1，返回**减之后**的值。

为什么必须是原子操作：`get` 再 `set` 是两步，`A: get=10` / `B: get=10` / `A: set=9` / `B: set=9`，卖了 2 件但只扣了 1 —— 超卖。`DECR` 在 Redis 内部一步完成。

一个细节：**key 不存在时 `DECR` 会先当 0 再减 1，结果是 -1**。所以 `SeckillController.doSeckill` 里判断的是 `stock < 0` 就售罄 —— 库存刚好卖完时最后一个是 0（成功），再减才是 -1（失败）。逻辑是对的。

**`incr`**
```java
public long incr(String key) { ... }   // 原子加 1，用于库存回补
```

**`hasKey`**
```java
public boolean hasKey(String key) {    // EXISTS key
    Boolean has = redisTemplate.hasKey(key);
    return Boolean.TRUE.equals(has);
}
```

**`delete`**
```java
public void delete(String key) { ... }  // DEL key
```

### 这个封装的不足（值得改）

1. **没有"谁加的锁谁释放"的校验**。真正的分布式锁要用 Lua 脚本校验 value 再删，否则可能删掉别人的锁。项目里只用于秒杀判重、不涉及释放，暂时安全。
2. **`decr` 返回 0 的兜底有歧义**。真返回 null 时给 0，调用方会误以为"库存刚好是 0"而不是"出错了"。建议抛异常。
3. **key 靠字符串拼接**，`RedisKeys.SECKILL_STOCK + goodsId` 到处写，拼错不报错。可以加一个 `buildKey(prefix, id)` 方法。
4. **没有 pipeline / 批量操作**。结果查询里如果要读多个 key，会变成多次 RTT。
5. **没有本地缓存**。内存标记 `seckillOverMap` 是在 Controller 里另外写的，没纳入这层封装。

## Q7. 项目里用了 Swagger / Knife4j 吗？

### 先分清三个东西

| 名字 | 是什么 | 角色 |
|---|---|---|
| **Swagger** | 一套 API 文档规范 + 工具集（现在规范叫 OpenAPI） | 定义"文档长什么样" |
| **Springfox** | Java 里实现 Swagger 规范的库 | 扫描注解，生成 `GET /v2/api-docs` 的 JSON |
| **Knife4j** | 国人封装的 Swagger UI 增强版（前身 swagger-bootstrap-ui） | 把那份 JSON 渲染成中文页面，带调试、导出 |

关系：`注解 → Springfox 扫描 → /v2/api-docs（JSON）→ Knife4j 渲染成 doc.html`。

**Knife4j 本身不生成文档**，它只是 UI + 自动配置。核心的 `Docket` 对象是 Springfox 的东西。

### 项目里的实际情况（分三档）

**依赖**：`common/pom.xml` 引入了 `knife4j-spring-boot-starter:2.0.7`，所以所有依赖 `common` 的服务都拿到了这个 jar（包括 seckill、user、order、search、web-app）。**这是问题的一半**——有 UI 但没有内容。

**逐个服务看**：

| 服务 | Knife4j jar | Docket 配置类 | `@Api` 注解 | 实际可用性 |
|---|---|---|---|---|
| **goods** | ✅ | ✅ `Knife4jConfiguration` | ✅ 3 个 Controller | ✅ **可用**：http://localhost:18001/doc.html |
| **search** | ✅ | ❌ | ✅ GoodsController | ⚠️ 有注解无 Docket，页面大概率空 |
| **seckill** | ✅ | ❌ | ❌ | ❌ yml 里配了 `status-page-url: .../doc.html`，但打开是空的 |
| **user** | ✅ | ❌ | ❌ | ❌ 同上（18006/doc.html） |
| **order** | ✅ | ❌ | ❌ | ❌ 没配也没注解 |
| **gateway** | ❌（不依赖 common） | ❌ | ❌ | ❌ |

**关键点**：`seckill-service` 和 `user-service` 的 yml 里写了
```yaml
eureka:
  instance:
    status-page-url: http://localhost:18007/doc.html
```
这**只是 Eureka 看板上显示的一个链接**，不代表那个页面有内容。没有 `@EnableSwagger2WebMvc` + `Docket`，Springfox 不会注册 `/v2/api-docs`，Knife4j 的 `doc.html` 打开后列表是空的（或报错）。

### goods-service 的配置在做什么

```java
@Configuration
@EnableSwagger2WebMvc                              // 开启 Springfox（旧写法，Swagger2）
public class Knife4jConfiguration {

    @Bean("defaultApi2")
    public Docket defaultApi2() {
        return new Docket(DocumentationType.SWAGGER_2)
                .apiInfo(new ApiInfoBuilder()
                        .description("# swagger-bootstrap-ui-demo RESTful APIs")
                        .version("1.0").build())
                .groupName("2.X版本")               // 页面左上角的分组名
                .select()
                .apis(RequestHandlerSelectors.basePackage(
                        "com.zhuawa.shop.goods.controller"))   // ★ 只扫这个包
                .paths(PathSelectors.any())
                .build();
    }
}
```

`Docket` 就是"这份文档包含哪些接口"的配置对象。`basePackage` 写死了 goods 的包 —— 所以**不能直接复制到别的服务**，复制过去会扫不到 Controller，文档还是空的。

### 要给其他服务加上，怎么做

**最小改法**（每个服务一份）：

```java
@Configuration
@EnableSwagger2WebMvc
public class Knife4jConfiguration {

    @Bean
    public Docket docket(Environment env) {
        // 用 spring.application.name 自动取服务名，避免复制时忘了改
        String appName = env.getProperty("spring.application.name");
        return new Docket(DocumentationType.SWAGGER_2)
                .apiInfo(new ApiInfoBuilder().title(appName + " API").version("1.0").build())
                .select()
                .apis(RequestHandlerSelectors.basePackage("com.zhuawa.shop." + appName))
                .paths(PathSelectors.any())
                .build();
    }
}
```

然后在 Controller 上加 `@Api(tags = "秒杀模块")`、方法加 `@ApiOperation("执行秒杀")`。

**更好的做法**：抽到 `common` 里做成自动配置（`spring.factories`），各服务引入即用。但注意 `gateway` 不能依赖 `common`（WebFlux 冲突），所以网关不会有文档——这反而是对的，网关没有 Controller。

### 版本兼容提醒（重要）

**Springfox 3.0 与 Spring Boot 2.6+ 不兼容**，启动报 `Failed to start bean 'documentationPluginsBootstrapper'`，原因是 Spring MVC 2.6 默认改用 `PathPatternParser`。解法是在 yml 加：

```yaml
spring:
  mvc:
    pathmatch:
      matching-strategy: ant_path_matcher
```

本项目是 **Boot 2.5.4 + Knife4j 2.0.7 + Springfox 3.0**，正好在兼容区间内，所以不需要这行。**但如果你以后升级 Boot，这里一定会踩。**

**替代方案**：新项目建议直接用 **springdoc-openapi**（`springdoc-openapi-ui`），它是为 Spring Boot 2.6+ / 3.x 设计的，不需要 `Docket`，零配置就能出文档，配合 Knife4j 4.x 也能用。
